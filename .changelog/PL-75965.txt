```release-note:bug
resource/harness_platform_token: Changing identity fields (`apikey_id`, `apikey_type`, `parent_id`, `account_id`, `org_id`, `project_id`) or `valid`/`scheduled_expire_time` now plans a destroy-and-create replacement instead of an in-place update.

Previous behavior: the provider planned an in-place update (`~ apikey_id = old -> new`) and called the token update API. Because a token's parent API key and scope are part of its server-side identity, the server cannot move a token this way — the update always failed (rejected or a 500 with endless SDK retries), so `terraform apply` could never succeed for these changes.

New behavior: Terraform plans `-/+ destroy and create replacement` and the apply succeeds by recreating the token. Note that replacement mints a NEW token value, so resources referencing the token's `value` attribute will see a planned update. Updates to `name`, `description`, `tags`, `valid_from` and `valid_to` are unchanged and still apply in place without recreating the token.
```

```release-note:bug
resource/harness_platform_token: `terraform destroy` no longer fails when the token was already deleted outside Terraform.

Previous behavior: destroy failed with `Error: resource with ID <id> not found: 404 Not Found`, blocking the whole destroy.

New behavior: a 404 on delete is treated as success (the token is already absent, which is the desired end state) and the destroy completes.
```
