# harness_chaos_composite_load_test (Resource)

Resource for a Harness composite load test.

Creates the pipeline that runs one load test and one chaos probe in parallel. It does not start a run. `identifier` is the stage id. It must start with a letter or underscore and contain only letters, digits, underscores, and `$`. A hyphen is not allowed. The pipeline id is that value with `_pipeline` appended, and that pipeline id must be at most 128 characters. That pipeline id is `pipeline_identifier`. Changing `identifier`, `org_id`, or `project_id` removes the composite load test. Destroy deletes that pipeline. The load test and the probe stay in place. `load_test_ref` is a load test identity in this project. A `LOCAL` copy and a `REFERENCE` template import are both valid. `tags` is a map. Empty probe `duration` and `infra_reference` are the default timeout and a runtime input. `10m` and `<+input>` are those same empty values.

## Example Usage

```terraform
resource "harness_chaos_composite_load_test" "checkout" {
  org_id     = "default"
  project_id = "demo"
  identifier = "checkout"
  name       = "Checkout"

  description = "Checkout path under load, with a chaos probe beside it."
  objective   = "Saturate checkout while the probe watches the payment service."

  load_test_ref = harness_chaos_load_test.checkout_k6.id

  tags = {
    team = "payments"
  }

  probe {
    identity        = "checkout_probe"
    infra_reference = harness_chaos_infrastructure_v2.payments.infra_id
    duration        = "5m"
  }
}
```

## Schema

### Required

- `identifier` (String) Stage identifier. Must start with a letter or underscore and contain only letters, digits, underscores, and `$`. A hyphen is not allowed. Changing it removes this composite load test. The pipeline id is this value with `_pipeline` appended and must be at most 128 characters.
- `load_test_ref` (String) Identity of the load test in this project. A load test created from a template is valid.
- `name` (String) Name of the composite load test.
- `org_id` (String) Organization identifier of the composite load test.
- `probe` (Block List, Max: 1) Chaos probe that runs in parallel with the load test. (see [below for nested schema](#nestedblock--probe))
- `project_id` (String) Project identifier of the composite load test.

### Optional

- `description` (String) Description stored on the composite load test.
- `objective` (String) Objective stored on the composite load test.
- `tags` (Map of String) Tags stored on the composite load test. This is a map. An empty map clears them.

### Read-Only

- `id` (String) The stage identifier.
- `pipeline_identifier` (String) Pipeline id stored for this stage. `{identifier}_pipeline`.

## Import

Import is supported using the following syntax:

The [`terraform import` command](https://developer.hashicorp.com/terraform/cli/commands/import) can be used, for example:

```shell
# Import id is org_id/project_id/identifier. identifier is the stage id.
# The pipeline id is {identifier}_pipeline and is not the Terraform id.
# Destroy deletes that pipeline. The load test and the probe stay in place.
terraform import harness_chaos_composite_load_test.checkout <org_id>/<project_id>/<identifier>
```
