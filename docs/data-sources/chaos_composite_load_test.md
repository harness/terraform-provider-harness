# harness_chaos_composite_load_test (Data Source)

Data source for a Harness composite load test. Reads the pipeline stored for the stage id. The Terraform id is that stage identifier. `pipeline_identifier` is `{identifier}_pipeline`.

## Example Usage

```terraform
data "harness_chaos_composite_load_test" "checkout" {
  org_id     = "default"
  project_id = "demo"
  identifier = "checkout"
}
```

## Schema

### Required

- `identifier` (String) Stage identifier. Must start with a letter or underscore and contain only letters, digits, underscores, and `$`. A hyphen is not allowed. Changing it removes this composite load test. The pipeline id is this value with `_pipeline` appended and must be at most 128 characters.
- `org_id` (String) Organization identifier of the composite load test.
- `project_id` (String) Project identifier of the composite load test.

### Read-Only

- `description` (String) Description stored on the composite load test.
- `id` (String) The stage identifier.
- `load_test_ref` (String) Identity of the load test in this project.
- `name` (String) Name of the composite load test.
- `objective` (String) Objective stored on the composite load test.
- `pipeline_identifier` (String) Pipeline id stored for this stage. `{identifier}_pipeline`.
- `probe` (List of Object) Chaos probe that runs in parallel with the load test. (see [below for nested schema](#nestedatt--probe))
- `tags` (Map of String) Tags stored on the composite load test.

### Nested Schema for `probe`

Read-Only:
